## 为什么造一个 IDE？

很多人问我：VS Code 不好用吗？为什么重复造轮子？

我的回答是：**造轮子不是为了替代轮子，而是为了理解轮子。**

IDE 是这个行业里复杂度最顶级的软件形态之一：编辑器、语言服务、文件系统、终端、版本控制、扩展系统、进程管理，每一个都是深水区。能把它们捏合成一个能用的产品，等于把前端工程、系统编程、算法设计、并发模型全练了一遍。

我想挑战一下自己。于是有了这个项目。

## 架构：三层进程隔离

IDEACODE 采用了类似 VS Code 的进程隔离架构：

```
渲染进程（React UI） ↔ 主进程（系统资源管理） ↔ 扩展宿主（Git/SSH/AI）
```

三个进程之间通过我自研的 **JSON-RPC 2.0 协议**通信，主进程持有系统资源的唯一操作权限，渲染进程和扩展进程崩溃互不影响。一个窗口卡死，其他窗口照常工作。

这套架构带来三个实打实的好处：

1. **故障隔离**：扩展崩了不会带崩整个 IDE
2. **安全隔离**：扩展拿不到底层系统 API，只能走主进程的受限桥接
3. **资源隔离**：CPU/内存大户（如 AI 扩展）跑在独立进程，不影响编辑流畅度

扩展宿主采用两段式销毁：收到 SIGTERM 先优雅卸载，2 秒无响应就 SIGKILL 强制清理，避免僵尸进程。

## 最骄傲的部分：23 个自研算法

这是整个项目里我最花心思、也最引以为豪的部分。IDE 里很多"理所当然"的功能，背后其实是硬核算法，而我没用现成库，全部自己写：

**FM-Index 全文搜索**
内置终端的滚动缓冲区里有大量 ANSI 转义序列，重复度极高。我用 FM-Index（BWT + LF-mapping）在压缩态下做全文检索——不用解压，直接在 BWT 上反向搜索，空间压缩率极高。这不是玩具实现，BWT 构建、C 表、Occ 表、反向搜索区间收缩，一个不少。

**W-TinyLFU 缓存**
Java Caffeine 缓存库的核心算法：Window LRU + SLRU 分级 + Count-Min Sketch 频率估计 + 周期衰减，完美平衡 LRU 的"缓存污染"和 LFU 的"缓存固化"。我用 TypeScript 完整重写了一遍。

**Node2Vec 文件推荐**
把项目文件看成一张图，文件是节点、共同编辑关系是边，用 Node2Vec 的二阶随机游走 + Skip-Gram 负采样学出每个文件的向量表示，基于余弦相似度推荐"你接下来可能要打开的文件"。

还有 PID 控制器（终端背压流控，带防积分饱和）、Count-Min Sketch、Kalman Filter、SimHash、Boyer-Moore、Trie、倒排索引、ARC 缓存、Lyapunov 调度器、增量熵、搜索 Bandit……

23 个算法，每一个的注释里都写了完整的数学原理和推导，欢迎去源码里拍砖。

**Rust + WASM 加速**
其中 fuzzy_search、levenshtein、simhash 三个高频算法我用 **Rust 重写**，wasm-pack 编译成 WebAssembly，跑在浏览器/Electron 里，比纯 JS 快一个量级，还写了基准测试对比。

## 三大内置扩展：Git / SSH / AI

IDEACODE 的扩展不是普通插件，而是运行在独立扩展宿主进程里的完整子系统：

**🌿 Git 集成**
解析 `git status --porcelain=v2` 精确区分 staged/changes/merge/untracked 四类状态；同一仓库命令串行执行，从根上杜绝 `.git/index.lock` 锁冲突；文件监听用 fs.watch + fs.watchFile 双兜底，解决 macOS rename 事件不可靠的问题。

**🔗 SSH 远程开发**
支持私钥/密码/keyboard-interactive 多认证，SFTP 远程文件树，SSH 远程终端，30s keepalive 保活。更妙的是扩展之间的联动：SSH 断开会自动通知 Git 扩展清理远程仓库、通知 AI 扩展切换 remoteFsAdapter。

**🤖 AI Agent**
多 LLM Provider（OpenAI / Anthropic / Ollama），内置 11 个工具自主编排任务，带 Plan Checklist 逐步执行、Token Budget 上下文预算、审计日志全量回溯。**默认只读**——AI 只能分析代码给建议，绝不直接改文件；要改，必须用户确认，且所有变更经 Diff 预览。

我最喜欢这个设计：**AI 的能力越强，越要把安全边界设计在最前面。**

## 诚实面对的几个取舍

写代码的人不吹牛，这几个点我得说清楚：

1. **依赖图分析用的是启发式正则，不是完整 AST**——够用且零依赖，但复杂语法会有漏匹配，这是刻意的取舍
2. **测试只写了 3 个**——时间都花在功能上了，这是我欠的债，正在补
3. **Monaco 首次加载有等待**——编辑器核心资源太大，这是 Monaco 的宿命，已做预加载优化
